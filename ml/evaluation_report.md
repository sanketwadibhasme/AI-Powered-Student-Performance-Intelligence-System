## 2. Dataset

- **Dataset:** UCI Student Performance (Cortez & Silva, 2008), Mathematics course —
  `ml/data/student-mat.csv`.
- **Rows used:** 395 (no missing values in the feature/target columns after `dropna`).
- **Class definition (classifier):** fail/pass threshold `G3 < 10` on the 0–20 grade
  scale, as defined by the project (grade below 10 = "at risk").

## 3. Evaluation methodology

- The evaluation script reuses the **exact** pipeline from `train_models.py`:
  same feature lists, same `train_test_split` calls (80/20, `random_state=42`,
  stratified for the classifier), same hyperparameters, and the same seed.
- Models were trained on the training split only and scored on the held-out
  **test** split. No metric is computed on training data. There are no fitted
  preprocessing transformers in this pipeline (all five features are numeric),
  so no risk of fitted-scaler leakage; the split itself is unchanged.
- Metrics (from `sklearn.metrics`):
  - Regression: `mean_absolute_error`, RMSE = `sqrt(mean_squared_error)`
    (sklearn 1.9.1 `root_mean_squared_error` equivalent).
  - Classification: `accuracy_score`, and `precision_score` / `recall_score` /
    `f1_score` with `average="macro"`, `zero_division=0`, over both label classes.

## 5. Test-set size and class balance

Test sets are disjoint from the training sets (80/20 split of the 395 rows).

| Split | n | Pass (`at_risk=0`) | At risk (`at_risk=1`) |
|---|---:|---:|---:|
| Full dataset | 395 | 265 | 130 |
| Classifier train | 316 | 212 | 104 |
| Classifier **test** | 79 | 53 | 26 |
| Regressor **test** | 79 | — | — |

The minority (at-risk) class is ~33% overall and ~32.9% of the test set. This
is a moderate imbalance, not extreme; the project mitigates it with
`class_weight="balanced"` and a stratified classifier split. Macro averaging is
therefore a fair choice, but per-class results from the original
`classification_report` remain viewable by running `train_models.py`.

## 6. Limitations and reproducibility notes

- **Small test set:** with only 79 test samples (26 at-risk), every metric
  carries noticeable variance; a single 80/20 split is used, consistent with the
  project's existing pipeline. For the paper, this is the project's current
  experimental procedure — no additional cross-validation was added because it
  would deviate from the existing evaluation process.
- **Seed dependence:** results are exact for `random_state=42`; changing the
  seed will shift all values. Reproduce with:
  `ml/.venv/Scripts/python.exe ml/evaluate_models.py`
- **No leakage checks needed beyond the split:** features are raw numeric
  columns; no scaler/encoder is fitted, so "fit on train only" holds trivially.
- **No changes** were made to `train_models.py`, `app.py`, saved models, the
  Flask API, Spring Boot backend, or frontend. Saved model artifacts and
  `models/metadata.json` were left untouched.
